## 历史基数测算

目标：男性2027年7月满60岁，企业职工参保，比较15/20/25/30年和60%/100%/200%/300%档位，共16种情况。

**16种情况已按用户确认的简化口径算出金额。** 使用用户提供的历史基数，统一适用于当年7月至次年6月，记账利率为0；个人/单位/账户计入比例固定为8%/16%/8%，养老金计发基数暂取12577元/月，60岁计发月数取139。2027年7月沿用2026年基数。结果是条件估算，不是官方核定待遇或历史真实缴费复原。

阅读 [测算报告](output/上海养老金测算报告.md)，或用电子表格软件打开 [16种情景测算表](output/16种情景测算.csv)。

## 参数

- `inputs/annual_contribution_limits.csv`：34年的用户原始上下限数值，生效月份按用户要求填写当年7月至次年6月。通用导入器仅映射明确填写了起止月份的区间；同年多次调整可增加行。
- [年度档位换算表](output/年度缴费基数换算.csv)：1993—1997年按用户确认的上限÷2推算100%基准；1998年起按上限÷3推算。各档受原始上下限约束，最低缴费基数单独保留。2020—2022年的最低基数不能直接当作模型的60%档。
- `inputs/config.json`：记录本轮计发基数假设12577元、60岁计发月数139、统一费率假设、7月切换规则及未来基数沿用政策。12577元由用户表中2026年缴费上限÷3得到，仅经用户同意用作养老金演算参数，不代表官方养老金计发基数。
- `inputs/monthly_parameters.csv`：1997年8月至2027年7月的360个月。`reference_base`为当期缴费基数基准；三项费率分别为个人、单位及个人账户计入比例，均使用小数，例如8%填0.08。不能把养老金计发基数当作所有年份的缴费基数。
- `inputs/interest_parameters.csv`：本轮按用户要求，所有年度利率设为0。权重同步填0，仅用于零利率计算，不表示官方计息规则；需要恢复利息时须重新填写历史利率和规则。

每条参数注明`source`。已核验值标注`verified`，用户提供值为`user_provided`，推算值为`derived_user_provided`，获准的演算假设为`assumption`；未来基数沿用标注`forecast`。后四者均不等于官方核验。月度基数来源单列在`base_status`与`base_source`，与费率来源分别记录。

## 运行

只依赖Python 3标准库，无需联网安装软件：

```bash
python3 prepare_estimate.py
python3 calculate.py
python3 -m unittest -v test_calculate.py
```

`prepare_estimate.py`会应用本轮已确认的假设并更新输入数据；若已手动更正数据，仅运行`calculate.py`即可复算，避免重新套用统一假设。通用年度表导入命令为`python3 import_annual_limits.py`。

金额全部可计算时退出码0，仍保留退休资格、参数官方核验等条件说明；缺参数时退出码2。CSV以UTF-8 BOM编码，便于中文电子表格软件读取。

首次补建空白模板使用`python3 calculate.py --init-inputs`，不会覆盖已有输入。输出金额保留到分，内部不逐月舍入。

## 计算边界

- 缴费结束月含2027年7月。15、20、25、30年分别从2012年8月、2007年8月、2002年8月、1997年8月起算。
- 目标档位为0.6、1、2、3，缴费基数受当月上下限约束。月度数据完整时，模型按实际月缴费基数与参考基准的比值月均值调整平均指数；忽略征收舍入差异。实际核定指数仍需核对官方口径。
- 基础养老金、个人账户养老金分别列示；本轮由于个人与账户计入比例同为8%且不计息，个人账户余额恰好等于个人累计缴费。单位缴费16%不加入个人账户。
- 无视同缴费年限、无其他过渡性待遇。60岁退休须符合弹性提前退休等条件；当前没有确认个人退休资格和起领时间。
- 个人账户按输入的各年规则计算`期初余额 + 当年计入 + 当年利息`。若官方规则不能用输入模板的年度单利权重表达，须调整模型，不能强套数据。
- 单元测试使用人工构造的算术样例，不能作为上海政策、费率或缴费基数的证据。结果仍需结合用户输入与演算假设阅读。
